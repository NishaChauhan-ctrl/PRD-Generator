---

## 1. System Architecture: The "Modular Intelligence" Flow

The goal is to move from **Static Prompting** to **Iterative Refinement**.

### High-Level Data Flow:

1. **Ingestion Layer:** `PyMuPDF` (PDFs) and `python-docx` (MRDs) extract text.
2. **Context Synthesis:** A "Summarizer" prompt condenses raw notes into a **Context Map** (Problem, Audience, Constraints).
3. **Modular Generation:** Instead of one massive prompt, the app calls GPT-3.5 for each PRD section individually. This prevents context "drift" and truncation.
4. **The Critique Loop (The 2026 Edge):** A final pass where a "Senior PM Agent" reviews the generated text for logic gaps.

---

## 2. Technical Stack Deep-Dive

* **Frontend/Hosting:** Streamlit (Clean, Python-native).
* **LLM Orchestration:** `LangChain` or `LiteLLM` (for easy swapping between GPT-3.5, GPT-4o, or Claude if the user wants).
* **File Parsing:** `Marker` (an emerging 2025/2026 favorite for high-accuracy PDF-to-Markdown conversion) or `PyMuPDF`.
* **State Management:** `st.session_state` to allow "Edit-in-Place" functionality.

---

## 3. UI/UX Design Map

Imagine a "Command Center" feel—minimalist, dark mode by default, high-contrast typography.

### A. The Sidebar (Configuration)

* **API Key Management:** Encrypted input field.
* **Project Meta:** Set the "Voice" (Technical, Business-First, Minimalist).
* **Template Selector:** Choose between *Standard PRD*, *Lean Canvas*, or *RFC (Request for Comments)*.

### B. The Workspace (Main Stage)

* **Phase 1: Knowledge Base:** Drag-and-drop zone for MRDs and meeting transcripts.
* **Phase 2: The Draftboard:** Use `st.tabs` for "Current Draft" and "AI Critique."
* **Phase 3: Interactive Editor:** Use `st.text_area` for each section so the PM can manually tweak the AI's output before exporting.

---

## 4. The "Feature differentiator" Logic

To make this GitHub-famous, implement **"Requirement Validation"** logic.

**The Logic Flow:**

1. **Input:** User provides a feature idea.
2. **Generation:** AI writes the "Metrics" section.
3. **Validation:** The app runs a secondary hidden prompt:
> *"Review these metrics for the 'Measures of Success' section. Are they SMART (Specific, Measurable, Achievable, Relevant, Time-bound)? Highlight any that are too vague."*


4. **UI Output:** Display a "Confidence Score" or "Reviewer's Notes" next to the generated text.

## 6. The "Pro" Prompt Engineering Strategy

Don't use a simple "Write a PRD" prompt. Use **Chain-of-Thought (CoT)** prompting in your backend:

```python

Act as a Principal Product Manager at a Tier-1 Tech firm.
Using the provided context: {context}
Step 1: Identify the core 'Job to be Done'.
Step 2: Outline 3-5 functional requirements.
Step 3: Define success metrics that are data-driven.
Format this in clean Markdown with bold headers.
"""
```
